## First protected-preview defect

Vicky opened the deployed v2 route on iPhone Safari. The app shell and runtime loaded, but the first home image was stopped by the AssetController eight-second timeout.

Remote verification confirmed `assets/rooms/home/day.jpg` exists on the v2 branch with the expected blob SHA. The controller had coupled a successful image `load` event to an unbounded `image.decode()` await while the original network timer kept running. A pending WebKit decode promise could therefore turn a loaded image into a false network failure.

The isolated fix makes decode best-effort with its own short bound, gives the actual network load a separate explicit deadline, and adds an automated never-settling-decode test. `/cloud`, `main`, live state, and all write endpoints remain untouched.

The next iPhone pass reached the new `asset · loading` state and then reported the more precise network timeout. Direct browser comparison confirmed the production-domain static image loads, the protected branch image redirects to Vercel login, and the corresponding public Supabase object loads. The v2 manifest now prefers the already-existing public Storage objects for home day, home night, and coffeeCorner, with repository-static paths retained as fallbacks. No Storage write or policy change was made.

A third iPhone pass timed out on both the verified public Storage source and the repository fallback. AssetController still routed both through a detached `new Image()` preload before assigning the real stage image, so that shared preloader was the remaining failure boundary. The controller now drives the connected stage `<img>` directly, listens once for its load/error result, validates natural dimensions, and performs only a bounded best-effort decode. This removes the duplicate request and assignment path rather than adding another source.
