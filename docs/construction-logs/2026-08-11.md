# Kitten Nest construction log · 2026-08-11

## Scope

Remove horizontal camera yo-yo when Alex and Vicky alternate dialogue in the three existing beach panoramas. Preserve the accepted image-world rule: bubbles and hotspots stay pinned to the base image, while only future rescue navigation may be viewport-fixed.

## Decision

One conversation is one camera unit. A new top-level `dialogueGroups` registry owns:

```text
scene owner
TextPort members
camera policy: groupLock
normalized base-image focusX
```

The artwork inspection showed that Vicky is foreground/POV in these frames rather than a second distant left-side subject. The previous `.36` Vicky bubble anchors therefore created false spatial separation of roughly one phone width. The selected group foci are `.51` for handhold, `.48` for bracelet, and `.56` for stall order. Both speakers in each scene now share that X while retaining separate vertical anchors.

## Runtime behavior

The first revealed member after scene entry waits for `layout:ready`, then centers the group focus once. The group remains focused for that scene entry, so later speaker switches and copy-width changes never invoke per-bubble reveal correction. Manual horizontal drag remains authoritative. Leaving and re-entering the scene resets the one-focus lifecycle.

Ungrouped panorama TextPorts keep the existing measured safe-edge reveal fallback. No route, scene stack, target id, queue, state field, MCP surface, Supabase object, or Storage asset changed.

## Shared story dialogue · manifest 0.4.0

The prior paired camera contract solved horizontal movement but still left two independent queue indices. A visitor could tap Alex, then Vicky, and accidentally splice together unrelated lines; consecutive Alex turns were impossible to express as one authored exchange. The data model now separates three axes explicitly:

```text
scene parent + push/back = exploration hierarchy
stories.seasideWalk.beats = named story order
dialogueGroups + dialogueScript = ordered turns inside one scene
```

The three groups use semantic ids (`seasideWalkHandholdSunsetMainDialogue`, `seasideWalkBraceletPromiseMainDialogue`, and `seasideWalkStallOrderMainDialogue`) rather than numbers. Each group maps `alex` and `vicky` to the two existing TextPorts and owns one shared runtime turn index. Any member action dispatches `dialogue.next`. Consecutive turns by the same speaker replace copy in the already visible member; a speaker switch hides the prior member; 200 ms input locking prevents accidental skips; completion closes the group and the next action restarts it.

The canonical state fields store ordered `{ speaker, text }` arrays. A shared browser/Node parser converts `@alex` / `@vicky` authoring blocks for `/write`, `/api/set-state`, and MCP. The writer now presents `conversation` and `ambient` separately. The six established per-speaker queues remain intact and independently writable; if a canonical script has never been published, the runtime interleaves those queues in deterministic Alex/Vicky round-robin order. Therefore deployment requires no live state rewrite and no Supabase table, RLS, Storage, route, asset, hotspot, coordinate, or controller migration.
