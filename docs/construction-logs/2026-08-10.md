# Kitten Nest construction log · 2026-08-10

## Scope

Continue the accepted v2 production runtime without reopening the legacy wrapper stack:

1. make ordinary navigation coordinates belong to the base image rather than the phone viewport;
2. register separate writable Alex and Vicky bubble queues for each existing beach scene;
3. expose the same exact target ids through MCP, the text-target envelope, and `/write`;
4. leave Supabase schema, policies, Storage, and live state untouched until an explicit publish.

## Navigation decision

Normal Go, Back, and Push are part of the authored scene world. Home, coffeeCorner, lapClose, and all three panoramas therefore own transparent `baseImageLocked` Hotspot objects. The old stage-level `scene.dock` owner and its DOM/CSS controls were removed.

A future rescue-navigation layer may be viewport-fixed, but it must be separately named, visually/semantically identifiable as rescue UI, and must never duplicate the normal route owner.

All direct scene navigation actions now receive the existing pointer-capture and 28 px drift-tolerance behavior.

## Beach target registration

The scene ids were already clear, so the writable target names reuse them and append the speaker/surface type:

```text
[coffeeCornerBeachHandholdSunsetBubble]
[coffeeCornerBeachHandholdSunsetVickyBubble]
[coffeeCornerBeachBraceletPromiseBubble]
[coffeeCornerBeachBraceletPromiseVickyBubble]
[coffeeCornerBeachStallOrderBubble]
[coffeeCornerBeachStallOrderVickyBubble]
```

Each is a `bubbleQueue` with four isolated fields: current, queue, index, and updatedAt. All six v2 text ports read these fields first and retain their approved manifest queues as fallback.

## Write surfaces

- `/api/mcp` loads all six ids from `data/text-targets.v1.json` through the existing generic `bubbleQueue` builder.
- `/api/set-state` enables the same six explicit ids for envelope publishing and does not enable the draft-only note/status targets.
- `/write` parses, drafts, bulk-publishes, summarizes, and emergency-writes the six canonical tags.
- `data/write-tag-registry.v1.json` maps one tag to one scene/object destination and includes all six in the deliberate write-all preset.
